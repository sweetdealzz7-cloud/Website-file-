Working demo · Make + Airtable

Gumroad sales into Airtable. Built so a missed sale cannot hide.

Most sales workflows look fine on a green dashboard and still lose sales. This one assumes pings arrive twice, arrive broken, arrive late or never arrive. Every case is handled and tested.

Everything below ran on synthetic data. The sale IDs start with GRDEMO and the emails are example.com. The "Gumroad list" in the daily check is a mock. It has not run on a live Gumroad account yet. See the last section.
How it works

Five steps. Nothing is dropped without a record.

1. ReceiveGumroad pings a private Make webhook for every sale.
2. CheckSale ID, email and price are validated before anything is written.
3. Write onceOne row per sale ID. A repeat ping updates the row. It never adds one.
4. Log failuresA bad ping goes to an error table with the exact reason.
5. Check dailyAirtable is compared with Gumroad. Gaps are filled and you get an alert.

Test 2 · Daily check

The check that catches what pings miss.

A ping can fail for reasons nobody sees. So once a day the workflow reads the sale list from Gumroad itself and compares it with Airtable. Here it ran against a mock list of 7 sales.

CaseWhat the check did
2 sales whose pings were broken (1002, 1003)Added from Gumroad's clean record. Marked RECOVERED.Recovered
2 sales whose pings never arrived (1099, 1100)Added and marked RECOVERED.Recovered
1 sale refunded in Gumroad but still "paid" in Airtable (1004)Status corrected to refunded.Fixed
Sales already correct (1001, 1005)Left alone.No change
Run it a second timeNothing added, nothing changed. Still 7 rows.Safe to repeat

The check is built to email the owner a short list for each of: recovered sales, corrected refunds, and bad pings still open in the error log.
